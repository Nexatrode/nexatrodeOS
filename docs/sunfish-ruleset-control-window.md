## Observation-only increment

Feature `sunfish-ruleset-control-window` inherits `sunfish-ruleset-reply-fifo`. It adds one bounded context window, starting after the original server-check WRQ is really accepted, or after the first accepted ruleset/EFS read in a stream without that WRQ. It records the opening accepted record, subsequent successfully decoded RX records (including recognized read notifications and OPEN), and successful checked TX publications after head store, validation and notification complete. Replayed early-control records are explicitly flagged as cached, rather than assigned current shared-FIFO arrival bounds. Failed decodes, invalid validation, blocked/staged writes and uncertain publication cannot be labeled accepted/committed records by this observer.

The window retains the first32 entries and the most recent32 in chronological order. Overflow increments an explicit omitted count; it does not imply complete traffic coverage. An advertisement with several intents prints its count and **first** size/ID only; it is not a reconstruction of the entire advertised pool. Fragments or packet types that lack a supported complete QRTR/TFTP projection leave that metadata unavailable. Raw opcode fields are numeric observations, not proof of service acceptance or application delivery.

The second and third distinct ruleset requests get their final GLINK record's existing RX-history bounds at the actual accepted transition. The original full opaque TFTP handle binds each cached observation. A normal queue admission assigns the transport reservation later; a read-only handle check attaches that original sequence without replacing the arrival bounds. Until the real sequence exists, the display suppresses that join. Existing request history is reused without another shared read, cursor sample or validation operation. Evicted spans and missing clocks remain unavailable. These are final-record visibility bounds, not the first fragment's arrival or the request's modem generation time.

The existing two exact FIFO watches still require original Core reservation/slot/route/length/intent ownership and a real RX_DONE/RX_DONE_REUSE transition. This new context freezes only after both original done transitions have been observed with the same reservation and remote intent and actual8-byte receipt, not an unrelated repeated ID. Context resets only on the existing successful fresh-generation/identity/empty-ring transport reset; stale/faulted resets retain evidence. A read-only StartupRead handle accessor adds no Core scheduling or ownership action. No server content/provider, queue policy, service/writer turn, FIFO/grant/credit check, close cleanup, retirement, capability or memory mapping changes.

Persistent context has an8192-byte compile-time bound; rendering borrows it rather than copying the whole window. Optional CPU clock reads, metadata copies and rendering can still perturb handset timing. The selected native stack audit and fresh packaging/capability checks gate delivery. The stack audit covers selected nested paths and excludes TLS, indirect calls and other descendants; it is not a whole-program worst-case stack certificate.

## RULESET CONTROL WINDOW

All numbers are hexadecimal. All-ones timestamps/metadata mean unavailable, distinct from known numeric zero. Rows2–6 show error, total/omitted/RX/TX records, exact completion mask (bit1 ruleset2, bit2 ruleset3), original peers/reservation low/high/remote intent and request absent/visible bounds, then request acceptance/publication/TX-tail/matching receipt visibility/processed completion/close clocks. Request and receipt timing joins require their own original reservation, not merely equal peer or intent numbers.

Rows8–23 show up to64 entries, four small lines per display row:

`US F CMD CH PARAM BYTES K A B TAG C D`

`F` bit1 means committed TX, bit2 cached early RX; ordinary accepted RX is0. `CMD/CH/PARAM/BYTES` are the GLINK command, wire channel, parameter and complete record length. Channel IDs are direction-specific; do not assume RX and TX channel numbers equal. `K/A/B` are QRTR type/source port/destination port when present. QRTR type7 is credit RESUME_TX; GLINK command7 is an intent request, command8 a grant ACK, command5 an advertisement, command6/14 a receive return, and command9 GLINK DATA (which can carry TFTP ERROR, not necessarily file DATA).

`TAG=5`: first advertised buffer size/ID in C/D, with count in PARAM. `TAG=A`: TFTP opcode/code in C and path-category/body-length in D (category in high byte). `TAG=D`: DEL_CLIENT node/port. Otherwise a parsed QMI flag is TAG and C/D are transaction/message. `TAG=F` with all-ones details means unavailable. Short/unsupported metadata does not become fabricated protocol state. RX timestamps are acceptance/processing observations; only the explicit request and receipt visibility summaries bound FIFO arrival. TX timestamps are after the existing successful publication sequence, not the modem read time.

Rows24–28 retain first ruleset and two EFS completion/close clocks, IPA counters/pending ID, ELF publication/consumption/visibility/completion/body-match/credit, original final ACK/close, ruleset total/omissions, MCFG RAM progress, PD, WLAN/WLFW, completion mask and unparsed count. EFS totals/omissions remain unavailable on this page. The two retained EFS entries are not asserted to cover every EFS request. The image keeps the previous FIFO observers internally; this page prints their key clocks alongside the new context.
