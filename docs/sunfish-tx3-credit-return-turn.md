# One checked QRTR credit before the original TX3 receive return

IMG_9813 narrows the parent own-return exclusion: 32 of 128 observed writer checks reached the final ready-credit veto. These are checks, not 32 packets. The photograph does not identify each credit or prove simultaneous fitting capacity. Actual TX3 and ELF receipt observations were prompt after publication; the remaining delay was before publication. See `sunfish-tx3-own-return-IMG_9813.md` for the archived observations and limits.

Feature `sunfish-tx3-credit-return-turn` extends the existing bounded handoff to **normal first ready QRTR credit → original TX3 RX_DONE → existing ready reply → fresh grant advertisement → positive ACK**, only while each stage's live checks permit it. It does not add a runtime drain loop or assume this entire window exists on the handset.

The new candidate requires an ordinary call, no protected WRQ/TFTP work or registry cooldown, no active converted-grant token, a positive ACK with its exact backing still Advertising, and the original unsent local ServiceRegistry transaction 3 reply to node 0/port 9. Its physical receive slot must still be ReplyQueued and done-pending. Its own-return, DATA and credit opportunities must be unused. The original reply must be the normal class 0 candidate with a fitting remote intent and the usual same-flow, outbound-wait and ordering checks. The credit is the normal first ready class 1 Resume, unsent and exactly 52 bytes. Existing converted/ELF credit choices retain precedence.

The existing checked credit publisher spends the credit attempt before calling the writer. One new private per-transmit Boolean records only an actual successful callback for that exact selected credit. That private success permits the existing own-return and ready-DATA eligibility checks to continue despite the spent credit-attempt latch. Another ready credit still vetoes those stages; they are not drained by this feature. The original reply handle, bytes and matching completion remain unchanged. No diagnostic field authorizes a write.

Each of the three attempts remains separately bounded. A blocked credit enables no later borrowed stage; normal arbitration handles progress. A blocked own return consumes that attempt, while a later ordinary return may still enable the unused existing DATA opportunity under fresh live checks. A blocked DATA attempt cannot borrow again. Advertisement remains before its matching ACK in every fallback. Uncertain writes or unwind quarantine the session. Reset clears the private state through normal construction.

A published credit keeps its real GLINK remote-intent ownership until its actual matching RX_DONE. A one-fitting-intent replay cannot reuse that intent for the reply until the receipt arrives. A second ready credit retains normal order. No FIFO validation, generation check, remote-intent reservation, QRTR credit accounting, queue capacity, firmware provider or client-close behavior is weakened. No new clock sample, transport I/O path or capability is introduced. Source normalization removes the marked child blocks and feature to recover parent production source `cf680e21` exactly.

Nine new Core cases cover clocked/clockless success, blocked writes at all three stages, uncertainty/unwind at each stage, one-intent receipt pressure, a second ready credit, scope/fit/already-advertised/bounded-call exclusions, and the real 88-byte avs/audio reply preserving msm/adsp/audio_pd and transaction 3. Two new real Adapter/FIFO cases check wrapped FIFO bytes, independent credit/reply ownership and completion, AD-before-ACK, and notification failures. Two functional removal controls independently disable credit choice and its actual-success latch; inherited controls and current/parent regressions remain required. Legacy scheduling assertions explicitly account for the newly selected credit-first path while retaining parent behavior with the child disabled.

The panel title is **TX3 CREDIT RETURN**. Existing TX3 MASK bits 17/18 show credit attempt/commit, 21/22 show original RX_DONE attempt/commit, and 19/20 show ready reply attempt/commit. All six together contribute `007E0000`; other mask bits may also be present. Existing eight own-return first-failure counters, both receipt/FIFO timelines, digest outcomes, original final ACK and independent IPA/WLAN/WLFW state remain visible. No producer trace is removed.

Delivery requires current Core/Owner/IRQ and parent regressions, source and rendered-panel checks, functional removal controls, selected native stack analysis, 304 capability mutation rejections, full payload identity, pinned SDK/Normal-NC reproduction and a byte-identical committed rebuild. The SDK is reused. These finite checks establish a bounded scheduling change, not a physical deadline or working WiFi. The next cold boot determines whether this eligible window occurs and whether startup advances.
