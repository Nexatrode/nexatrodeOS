# One bounded overlap for the second identical EFS ERROR

## Native versus the saved Linux exchange

IMG_9776 completed its first EFS error before the client closed, but its second same-peer request spent 687.540 ms between dispatch and queue admission, with two FlowBusy outcomes. The second reply ultimately published 1,052.392 ms after acceptance and completed 7,103.323 ms after client close. Its consumption and RX_DONE visibility were not captured by the first-reply watcher, so those completion seconds cannot be assigned to modem generation, FIFO visibility or host processing from that photo.

The native `queue_tftp_transmit` rejects any existing nonempty transmit to the same QRTR destination before normal slot/QRTR-credit admission. Except for the existing tightly scoped OACK-repeat exception, a fully published EFS error therefore blocks the next same-peer reply until its actual GLINK receipt and retirement. The second successful admission follows the first completion in IMG_9776. That rule is a sufficient blocker while the first reply remains outstanding; failed-attempt timestamps and any simultaneous pressure are not separately shown.

The successful cold Linux journal contains one modem_efs RRQ, followed by explicit missing-file rejection, then a WLAN firmware request before later MCFG/digest work. It does not show an equivalent second same-peer EFS retransmission or establish the modem's private startup deadline. The saved `tqftpserv.c` opens a fresh connected QRTR socket for each RRQ and sends ERROR1 for a missing file; it contains no userspace GLINK-RX_DONE wait before accepting another RRQ. Its socket allocation/lifetime is not reproduced here. Both pinned upstream and Android/Lineage QRTR implementations use destination credit thresholds low 5/high 10. Downstream GLINK selects an available fitting remote intent and returns that individual intent on RX_DONE; it does not impose this native blanket one-transmit-per-destination rule. These sources establish selected host semantics, not the proprietary modem's launch decision or byte identity with every reference kernel.

## Narrow authority and unchanged transport boundaries

`sunfish-efs-reply-overlap` is explicitly enabled by the native runtime and default-off in the Core. A separate authoritative Core ledger captures the first two accepted exact-path EFS RRQs. It retains the actual opaque handles, actual peer and up to 256 bytes of the first complete TFTP request, excluding QRTR padding. The second must have the same peer and byte-identical full request. A larger first request, a different second request or peer, and later requests do not acquire an exception. The ledger is independent of diagnostic `StartupRead` entries and optional clocks.

Successful ordinary queue admission of the first ERROR binds its actual transmit slot and complete QRTR reservation token. Only the second handle's identical prepared ERROR1/19-byte response, on the same native server-check transfer port and route, can propose overlap with that slot. The original slot must still contain that exact token, source/destination and body, be fully published on a busy remote intent, and lack GLINK completion. Decoded same-peer DEL_CLIENT fences the exception before deferred close handling. Reset clears the entire ledger and disables it; old-generation handles cannot rebind it.

The proposal uses the existing overlap parameter and its exact source/body/fully-published check. It does not bypass any other conflicting transmit, enlarge the normal eight-slot table, use the reserved OACK slot, create a QRTR credit, force a fitting remote intent, change writer arbitration, or release the original buffer. The second response reserves its own normal slot, QRTR token and remote intent. Ordinary capacity/credit/backpressure can still reject admission. The successful second admission spends the opportunity; a third packet cannot borrow it. If the first already completed, ordinary admission remains the fallback and no overlap is counted. Neither outstanding reply is retired by client close; each requires its real matching completion.

The retained Owner, first EFS service handoff, normal server policy, prepared-reply identity, receive-slot release, FIFO validation and advertisement-before-grant-ACK order remain in their prior paths. No new raw shared-memory read, mapping, IRQ/SMC capability or optional clock hook is introduced. The ledger copies checked host data and normal queue results. Earlier admission can change scheduling and the frequency/order of existing operations.

## Offline evidence and next image

Actual Owner schedules exercise both completion orders while preserving each original transaction, and compare the complete ordered QRTR packets with the ordinary serial baseline. Core/Owner cases cover an unpublished predecessor, changed request/options or reply, a third request, normal slot exhaustion, slot reuse with a different token but identical peer/body, QRTR high-watermark rejection followed by a real RESUME_TX, both published replies surviving client close, a known close before second admission, an uncertain head-store fault, and logical reset. Expected failing controls disable admission, remove exact-request matching, or remove the original-token guard. Full prior/default-off, grant/credit, fault, backpressure, registry and close suites remain required.

**EFS REPLY OVERLAP** retains both EFS acceptance/dispatch/queue/publication/completion/close timelines and the original ACK/ELF/IPA/WLAN outcomes. In this explicitly enabled runtime, the existing FIFO watcher now follows the second EFS reply; the row label is **EFS2 KEY LO HI INTENT ARM**. It uses the same validated cursor samples, exact reservation/intent matching and numeric visibility bounds. Default-off fixtures continue to watch the first reply. The first EFS's full lifecycle clocks remain visible in its own entry.

Row16 appends **PAIR** to `VISIBLE CLOSE FIN EVICT STOP CMDS`. This word packs ledger flags in bits 0..7, successful overlap admissions in bits 8..15, and offers in bits 16..31. Flags are 1 enabled, 2 first request captured, 4 second captured, 8 exact request/peer match, 16 original transmit bound, 32 peer closed, 64 second queued. For example `0001017F` means one offer, one admitted overlap, and all those flags set at the settled close. A normal post-completion second queue can set 64 while overlap admissions stay 0. Offers can exceed admissions under normal capacity or credit pressure. Displayed counters are width-limited; original ledger counters saturate rather than wrap.

CMDS retains the existing first EFS writer-group projection, least-significant byte first; command 9 means GLINK DATA carrying a TFTP ERROR, not a firmware DATA block. Row17 retains the extra-service and earlier-writer counters. The next boot tests whether the second request actually matches, queues while the first remains outstanding, publishes sooner, is read promptly, and gets its RX_DONE before close. Zero WLAN/WLFW remains possible. This is a bounded admission experiment with exact identity preservation, not a claim that the missing-file exchanges are the final WLAN prerequisite.
