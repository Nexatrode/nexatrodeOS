# Ready-path startup outcome

IMG_9805 supplied the missing current full-pool capture. The registry and ELF took the already-known fast path; neither new ready handoff ran. The queue retry succeeded. The important remaining question is what that boot did **after** the fast early path, without mistaking a historical IPA-complete latch or transient unsent queue record for its settled protocol state.

Feature `sunfish-ready-startup-outcome` inherits `sunfish-registry-ready-handoffs`. It selects the **READY STARTUP OUTCOME** renderer before the adaptive pool/reply renderer. It changes no transport/Owner/IRQ policy, capability, request validation, FIFO boundary, grant order, credit condition, timer sample or storage. All getters and retained observations already exist. Stripping its two marked display blocks and Cargo feature recovers the parent production source exactly.

The one panel connects TX3/TX4/ELF receive/queue/publication/completion, frozen publication masks, both handoff observations and queue-wait reasons with live IPA flags and request/publication counts. It also shows the exact ELF host credit, original WRQ/DATA/final ACK, the first two ruleset and first two EFS records with queue/publication/completion/close and server/client result, the first accepted TFTP request after ELF, and the bound MCFG record's publication/completion/cancellation and client ending. Read totals/omissions, MCFG file progress, PD, WLAN RRQs and WLFW remain visible. All row values are hexadecimal; clocks are host microseconds from runtime start, unavailable `FFFFFFFF`, while status/count fields keep their own definitions.

Rows3 and4 deliberately distinguish Core versus Owner completion observations. Row9 host PUB means a remote intent was assigned to that exact retained credit; it does not give a completion timestamp. Row10 LIVE IPA includes protocol-complete bit4 plus pending/queued/held/failed bits, independently of row28 HIST IPA. Row11 includes unhandled IPA request count/last ID. Rows14–21 contain bounded ruleset/EFS records; counts and omissions on row26 disclose missing later records. Each request has its own retained identity; endpoint equality cannot join it with another request. Row22 is the first TFTP request **accepted** after exact ELF completion, not proof of when the modem generated it. Row23 retains MCFG sequence low/high to separate original/replacement replies. Row28 OTHER category/peer reuses the first other path observation and cannot identify an arbitrary pathname from its category alone.
