# Exact TX3 and ELF completion visibility after paired publication

IMG_9811 published transaction 3 in 260.962ms and ELF in 170.963ms after queueing. The existing converted-grant TX3 path and the paired ready-credit/ELF path both committed. ELF receive-to-Owner completion improved to 2,999.113ms, but the publication-to-completion intervals grew to 4,119.376ms for TX3 and 1,803.327ms for ELF. WLAN/WLFW remained zero. Publication alone cannot divide those waits into remote consumption, RX_DONE appearance and host FIFO processing.

## Reuse and source comparison

The retained TX3 FIFO observer already answers this question for its exact predecessor. IMG_9708 showed peer-tail crossing 6.155ms after publication, then 7,409.373ms to matching receipt visibility and another 643.775ms to decoding. IMG_9709 similarly showed 6.171ms to consumption, 6,549.554ms consumption-to-visibility and 826.207ms visibility-to-decoding. The latter wire log included service announcements, 52-byte grant cycles and earlier reusable receipts. Those are separate boots; their clocks, prefix lengths and packet identities cannot explain IMG_9811 by substitution.

Pinned Linux qcom_glink_native.c clears a remote intent's in-use state on actual RX_DONE, removes a non-reusable intent, and wakes reusable-intent waiters for reuse. Its receive-return path and Android's corresponding worker path can defer sending RX_DONE. This establishes that FIFO consumption is distinct from the actual return; it does not expose the modem firmware's private service scheduling or establish why this boot's response was late. Retiring a native published reply at peer-tail crossing would weaken ownership and is not part of this change. QRTR flow credits also remain separate from GLINK receipts.

## Bounded ELF observation

Feature `sunfish-registry-receipt-fifo` inherits the delivered pressure profile and adds a single ELF observation beside the existing TX3 one. The Core read-only getter exposes the exact existing first-ELF opaque request only after its admitted writer has actually finished and its exchange identity agrees with the first ELF window. A successful final DATA publication arms one retained FIFO window using the checked writer's existing validated cursor pair, actual remote intent and unread count. Idle, missing fit, failed/uncertain publication and unrelated pre-ELF DATA do not arm it.

The observer uses the existing RegistryReplyWindow algorithm. Normal validated cursor samples advance the transport-consumption and RX-head history; validation failure cannot advance it. There are no added descriptor/FIFO reads, writes, publication calls or runtime receive turns. Optional diagnostic clock sampling adds one call when arming and a start/end pair during each active window sample. It stops sampling on the normal decoder's exact generation/session-bound ReplyRxDone handle. A matching intent number alone is insufficient. The exact Core receipt timestamp is copied from its retained target receipt; the Owner timestamp remains independently displayed. Frozen results survive later activity and remote-intent reuse; successful transport reset clears the watch.

This is diagnostic state, never a selector or lifecycle input. No scheduling, buffer lifetime, queue capacity, grant advertisement-before-ACK, credit priority, retry, fault quarantine or firmware reply behavior changes. Instrumentation may affect measured timing; a single instrumented boot is not a controlled performance benchmark. Lost bounded history leaves unavailable bounds unavailable.

## Panel interpretation

Title: **REGISTRY RECEIPT FIFO**. Both original timelines, publication masks and all priority/grant counters remain on the same page. TX3 and ELF TAIL/ABS/VIS/AHEAD/FINISHED/EVICT rows divide each exact receipt path. TAIL is host-observed validated peer-tail crossing, not application acceptance or the exact modem read instant. ABS/VIS bound the matching receipt's appearance in sampled RX-head history. AHEAD is preceding bytes, not packet identity. FINISHED is clock-independent; zero means unfinished or no window, while unknown bounds remain FFFFFFFF. EVICT counts overwritten advance-history entries, not dropped packets.

ELF ARM/UNREAD/INTENT/CORE/OWNER retains the initial snapshot and separates normal Core decoding from later Owner handling. TX3's Core completion remains in its original timeline. The first converted-grant snapshot is not a log of all grants. Writer spans, admission failures, original final ACK, exact digest reservation identities and their publication/completion/close, live IPA state/ELF credit/body match, and independent WLAN/WLFW status remain visible. First/latest detailed failure/retry snapshots and digest receive/queue timestamps remain retained in producers but are not all rendered on this page.

If TAIL is prompt but VIS is late, the large interval is before the matching receipt becomes observable at the host. If VIS is early and CORE is late, preceding FIFO work and normal receive processing need examination. CORE-to-OWNER separates later host dispatch. These are observation intervals; none alone identifies all intervening packets or proves a WLAN prerequisite.
