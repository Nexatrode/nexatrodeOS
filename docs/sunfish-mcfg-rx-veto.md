# MCFG receive-veto capture

IMG_9767 established that the new bounded MCFG publication hook was reached three times, but each call yielded to RX and none committed a write. Its counters did not identify the pending record or distinguish the initial cursor veto from an arrival before publishing the head. The original reply still canceled at close; an earlier ERROR completed normally. IPA was complete, WLAN RRQ and WLFW were zero.

`sunfish-mcfg-rx-veto-trace` retains the existing queued-turn behavior and adds observations only. It records cached validated RX cursors at the two existing veto branches. After a veto, it copies headers already read by normal `poll_receive`, including the startup early-record queue, and records normal idle/partial observations. It stops that capture at the first validated normal idle observation, rearms on a later veto, and stops observing a watched request once published, completed or canceled. It adds no FIFO reads, cursor samples, validation calls, receive turns, writes, queue changes or authority. Optional existing clock calls and fixed diagnostic copying can perturb timing.

The first four events and last eight are retained, with total and omitted counts. Tag 1 means initial snapshot veto; 2 means RX arrived before publishing the head (recorded just after the normal callback returns); 3 means a normal framing-validated header; 4 a retained early header; 5 normal validated idle; 6 partial/pending receive. A header is observed before semantic ingestion, so it does not claim successful packet acceptance or tail advancement. A later fault remains terminal. A missing timestamp is unknown, not zero. The watched reservation belongs to the original diagnostic target, not necessarily the response that armed a global eligible burst.

The panel **MCFG RX VETO TRACE** preserves target/predecessor admission, publication/completion/cancellation, ELF timing, IPA outcomes, original ACK and host-credit summary. Row 14 gives total, omitted, queued-turn calls, committed writes, RX vetoes and backpressure stops. Rows 15–26 show one event each:

- First line: time, tag, call number, cached RX bytes, early-record count, watched reservation low/high.
- Second line: GLINK command, channel, parameter, framed record size, QRTR kind, source/destination ports. For a decoded DEL_CLIENT, the last two fields are the actual closing node/port. QRTR fields are available only for an initial DATA header; continuation fragments stay unknown.

Rows 27–28 retain close cleanup counts, committed MCFG writes/reads, IPA complete, PD state, WLAN requests and WLFW servers. Framebuffer verification uses the physical 57-character budget. No payload body, filename content, network credential or memory dump is captured.

The exact marked additions are compared against `9bf1ee0c`; disabled-feature sources and Core/Owner arbitration remain unchanged. Tests cover an actual pending record followed by idle and normal retry, an arrival during write before head, semantic faults without tail/head publication, bounded clockless retention, DEL_CLIENT endpoints and continuation unknowns. On/off replay compares committed bytes and Fake I/O operation sequences with the same synthetic schedule. Negative controls remove the veto-stage event or normal-header event and must fail the corresponding component test. Neither synthetic replay nor this diagnostic proves a physical deadline or WLAN readiness.

The private ready profile is `.cache/sunfish-native-wifi/private/native-mcfg-rx-veto-v1`; prior delivered profiles and manifests remain immutable. Build/stack/packed-authority verification and the committed source revision are recorded in its final manifest. The SDK is reused from pinned prior components, the native program is rebuilt, and actual packed loader/report/CapDL/archive contents are independently reproduced. Device commands remain manual.
