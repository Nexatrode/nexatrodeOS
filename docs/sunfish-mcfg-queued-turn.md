# Bounded MCFG reply turn

The IMG_9765 predecessor result showed a real earlier 52-byte ERROR completion, followed by successful admission of the original reply. Its only retained writer pass sent the slot-releasing RX_DONE, and the client subsequently closed. WLAN requests and WLFW servers remained zero. This is evidence for testing an earlier normal writer opportunity; it does not establish MCFG as the prerequisite for WLAN startup.

The `sunfish-mcfg-queued-turn` feature gives the normal writer at most four immediate attempts after an authoritative absent-MCFG ERROR successfully enters the ordinary transmit queue. The native runtime explicitly enables the Owner option; it defaults to disabled. Scope requires the exact built-in missing-file reply and the server's known MCFG peer/transfer-port association. Observer identities, clocks and counters never authorize transmission.

Every attempt runs the existing arbiter and checked writer. A fresh validated receive snapshot must be empty before selection, with existing RX checks also enforced before writing and before publishing the head. A pending or racing close therefore yields to normal receive processing. A successful receive return, advertisement, or grant ACK may continue the burst; any DATA, other operation, idle state, backpressure or fault ends it. A QRTR credit selected by the normal arbiter retains its turn and ends the burst. No grant ACK bypasses its advertisement, no published slot retires early, and GLINK completion still requires the real matching receipt. Ordinary retries remain available after a blocked or vetoed attempt; uncertain writes retain terminal fault handling.

The change targets the observed queue-to-writer wait. It does not change the preceding completion-to-queue delay, file availability, digest handling, Core arbitration, QRTR flow policy, interrupt authorization, table-validation boundaries, or the modem's proprietary startup decisions. Saved Linux evidence reaches WLAN firmware before the later MCFG/digest exchange; fixing this local delay alone is not proof that WLAN will start.

Offline tests exercise the actual Owner and Adapter: full receive pool followed by RX_DONE → advertisement → positive ACK → ERROR, QRTR credit selection, exact scope and default-off behavior, pending/racing RX, FIFO backpressure, terminal faults, close cleanup and real receipt identity. Negative controls remove the handoff and the pre-head RX guard separately and must make their corresponding tests fail. Disabled-feature source normalization compares exact marked additions against `a5b582a9`; underlying Core and flow sources remain byte-for-byte unchanged.

The new **MCFG QUEUED TURN** panel retains predecessor, original reservation, writer/grant and ELF/IPA/WLAN outcomes. Row 25 reports `TURN CALLS WRITES RX VETO BLOCK`. Calls count admitted bursts; writes count committed ordinary operations, not just the watched reply. First writer rows include the watched reservation sequence, not necessarily the packet selected. QRTR header fields describe initial DATA records only; continuation words are not decoded as headers. Framebuffer tests enforce the actual 57-character row budget.

The private build profile is `.cache/sunfish-native-wifi/private/native-mcfg-queued-turn-v1`. The ready manifest records the exact committed revision, native ELF and boot-image hashes, source pins, stack limits, actual packed capability audit and test results. Previously delivered profiles remain immutable. The SDK is reused from its pinned prior build; the native program is rebuilt and the actual loader/report/CapDL and packed archive are independently reproduced and checked. No device command is run automatically.
