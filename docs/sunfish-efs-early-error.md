# One early checked writer group for the first EFS ERROR

IMG_9775 shows the modem consuming the first modem_efs ERROR within 6.200 ms of publication. Its matching RX_DONE was still absent 7,654.631 ms after that observed tail crossing and processed 164.275 ms after first visibility. The large completion gap is mostly before shared-RX arrival. However, the host initially publishes that ERROR 1,492.993 ms after accepting the RRQ. A late response to a timing-out client remains a hypothesis; the capture does not establish the private deadline, application acceptance or delayed-receipt reason.

`sunfish-efs-early-error-turn` gives the already-queued original EFS ERROR one bounded opportunity through the existing normal writer. It does not claim to fix the preceding 933.987 ms service wait or guarantee publication within one second. There is no evidence-backed reason here to fabricate MCFG/EFS data, add a host restart command or clear a published flow without its real receipt.

## Scope and authority

The Owner is default-off and the selected native runtime explicitly enables it during normal service activation. The actual validated TFTP receive path, not the diagnostic trace, retains the first EFS RRQ's opaque handle and actual peer. Validated same-peer client-close events, including paused MCFG/firmware close paths, mark it closed. The scope cannot rebind to a newer request or another peer.

Only successful ordinary queue admission of that exact handle/peer's prepared 19-byte `file not found` ERROR can consume the opportunity. Ruleset, other MCFG/firmware responses, later same-peer requests, failed admission and already-known closes cannot take it. The one-shot latch is spent before fallible I/O. The existing receive-slot release, retained reply removal, continuation scheduling, normal queue capacity and QRTR flow checks remain in their original order. No observation timestamp, diagnostic flags or copied peer port grants I/O authority.

The adapter calls its existing checked writer at most four times. Each uses the existing fresh-RX guard; RX backlog yields and leaves normal continuation. Only RX_DONE, receive-intent advertisement and intent-request ACK may be followed by another call. Any DATA or other ordinary operation ends the group. Ordinary selection may choose another packet; this code never selects or forces the EFS transmit record. Advertisement-before-ACK, fitting intents, predecessor ordering and credit checks remain Core decisions.

Backpressure preserves the existing read-notification result and stops. Awaiting-intent/ordinary idle stop. Errors remain terminal through the Owner; an uncertain head store cannot repeat the opportunity or fabricate a completion. Published buffers remain owned until matching real RX_DONE. No new IRQ, SMC, mapping or runtime readiness authority is added. Optional existing diagnostic clocks can change frequency/order through the extra normal writer calls; this is not an unchanged-scheduling experiment.

## Offline evidence and panel

The actual Owner tests compare default-off and enabled first/second EFS responses with real matching completions and an unrelated ruleset prelude. Wire bytes remain identical for those synthetic schedules. Further cases cover a fresh RX veto with ordinary fallback and no repeated opportunity, a TX-head store fault after the write took effect, and no borrowed turn after known close. Actual adapter grant-pressure fixtures retain RX_DONE → advertisement → grant ACK → DATA, and preserve read-notification fallback on blocked TX. Expected failing controls suppress the turn or remove the close guard. Full IRQ, fault, backpressure, registry, close and arrival-order suites remain required.

**MODEM EFS EARLY ERROR** keeps the first EFS FIFO consumption/visibility history and both EFS request timelines. Row 16 appends the early-turn stop reason; row 17 displays calls, committed Session writes, RX vetoes and blocked outcomes. Stop 0 is no run or four-call bound exhaustion (use calls/writes to distinguish), 1 is DATA/other ordinary operation, 2 RX veto, 3 blocked TX, 4 awaiting intent, 5 ordinary idle, 6 terminal writer error. A Session write can be control work; the first EFS publication clock, not the write count alone, proves that target went out.
