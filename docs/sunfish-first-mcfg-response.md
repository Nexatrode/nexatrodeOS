## Capture scope

Feature `sunfish-first-mcfg-response` inherits the delivered pool/wire profile. One marked observation condition lets the existing MCFG watcher bind the first exact `/readwrite/mcfg.tmp` RRQ accepted after the first ELF request has created its trace, including one before ELF publication or matching completion. This is acceptance order, not firmware generation order. It does not retroactively bind a request accepted before ELF, and it never rebinds to a retry or another peer. The existing first-other-path latch still starts after ELF completion. No duplicate capture object or persistent storage is added.

All existing dispatch, normal queue-attempt/blocker, publication, exact reservation/remote-intent completion, cancellation and client-ending observations then follow that original opaque handle. File presence is sampled by the existing pure server getter at dispatch. Before dispatch, an unavailable FILE field is not evidence the file was absent. The first client ending requires the observed transfer port and exact peer; repeated-RRQ counts are same-peer observations, not byte-equality proofs.

Core arbitration, Owner/Runtime/IRQ service code, FIFO/native validation, grant advertisement-before-ACK, QRTR credits, writer budgets, backpressure, real receipt lifetimes, file/server/firmware policies and close cleanup are unchanged. The observation state is used for diagnostics, not publication authority. Existing optional clock sites may run earlier/more often, parsing/copying and repaint can perturb timing, and a single bounded watched request still omits other request-specific histories. Source normalization strips the one marked condition/renderer dispatch and Cargo feature to recover parent production source `2ff2b35d` exactly. The separate mainline Maps session-lock overlay `a524912e` is normalized only by its exact pinned Cargo/vault sources; that feature is disabled in this native image and the final committed rebuild must still match the packaged native ELF.
