## Offline finding and bounded capture

The existing per-transmit `RegistryPublication` already accumulates arbiter outcomes, priority/grant gates and ACK observations for every registry reply, including ELF. The retained older snapshots freeze transactions3/4, so their history must not be substituted for the exact ELF reply. A queued dispatch is an ordinary receive/write pass: it can send a control record, another packet, encounter an intent shortage or yield to a blocked FIFO while preserving grant and credit ordering. Flags0F alone do not select one of those explanations.

`sunfish-elf-writer-trace` preserves the verified first-slot and queued handoffs. Observation begins only after the exact first accepted ELF request has passed normal queue admission. It binds the existing opaque request identity, not transaction5 alone or a transmit-slot index. It records Core `publish_inner` entry, the already-constructed header actually presented to its writer callback, and the existing post-callback publication observation. The existing per-transmit counters/gates are copied at each completed observation, then frozen when the exact reply's full data commit advances its sent length to its full length. Later receipts, transmit-slot/intent reuse and unrelated publications cannot overwrite it; reset clears the existing ELF window and its attached writer capture.

Records retain opening four/latest four with an omitted count. Three focused Core cases exercise blocked callbacks, exact target/full-publication freeze, retained packet identity, slot reuse, history bounds, clockless and regressed clocks, uncertain callback and reset. The established byte-parity fixtures compare protocol output with/without observation; actual Owner/Router suites retain grant/credit/lifecycle/fault controls. The existing deterministic Owner clock fixture accounts for two extra writer boundary observations rather than mislabeling the shifted synthetic clock values as protocol delay.

The whole ELF observation remains bounded to3KiB, with native selected-stack auditing. There is no allocation, extra device read, record reordering, new writer attempt or queue-policy change. Removing the feature-gated hooks reproduces the prior Core writer/publication observer bodies exactly. Runtime service methods, Owner handoff/transport loops, FIFO validation, selectors, grant advertisement-before-ACK, QRTR credits, close handling and native I/O callbacks are unchanged. This is self-review and finite testing, not a complete hardware-interleaving or stack proof.

## ELF WRITER PUBLICATION panel

All values are hexadecimal; ages and converted spans are microseconds. Missing times areFFFFFFFF. Counts and flags still advance without a clock. Snapshot metadata is observation, never scheduling/admission authority.

- **ELF RX QUEUE PUB DONE:** existing accepted request, queue, Owner-observed full publication and exact Owner completion.
- **SLOT TURN ADMIT SEQ N RX:** consumed first-slot continuation, admission sequence, earlier-owner count and last prior receipt transaction. **QUEUED TURN ENTER END FLAGS** retains the ordinary queued handoff;0F means entered/returned,1F additionally establishes exact publication by its end.
- **WRITER FIRST LAST FINISHED:** first Core pass entry, last observed pass end and exact full-commit freeze flag. **PASSES TIMED OMIT ACTIVE:** Core entries, completed non-regressed timed intervals, omitted history and an entry not yet matched by an end observation. An early error/uncertain write may leave an active entry; this is not a committed publication.
- **PASS US MAX GAP US BAD CLOCK:** sum of available non-regressed Core entry→post-callback observation intervals, maximum available prior-end→next-entry interval, and backward-clock flag. Compare timed count with total passes. These spans do not include all of the Core post-observation commit tail. Gaps include that tail, outer FIFO/native validation, other services and scheduling; they are not necessarily idle time or pure service work. Queue→first entry and last end→Owner publication are shown separately. Additional clock/metadata overhead can perturb timings.
- **PUB CALLS MASK TXN BYTES:** frozen existing exact-target `RegistryPublication`. Calls count observed arbiter outcomes, not a promise each call wrote data. Mask bits0..6: no suitable intent, outstanding request, control selected, other data selected, selected but blocked, successful DATA callback, outbound intent request selected. Higher existing experiment bits are preserved; bit7 priority publication,8/9 borrowed attempt/commit,10 conversion armed,11/12 conversion attempt/commit,13 conversion seen,14 own return pending,15 no exact candidate,16 opportunity already used;17/18 mark the existing same-pass publication priority paths. A selected control/outbound-request bit does not establish its commit by itself.
- Two **TURN GATES** rows count the existing first failing priority condition:0 cooldown,1 ready TFTP,2 pending intent ACK,3 own receive return,4 no candidate,5 different candidate,6 priority/credit unavailable,7 selected. Three **GRANT GATES** rows count the existing first condition:0 no pending ACK,1 denial,2 no backing,3 no yield/conversion eligibility,4 turn already used,5 TFTP,6 WRQ return,7 own return,8 grant opportunity already used,9 candidate mismatch,10 priority mismatch,11 eligible. The actual arbiter remains authoritative.
- **ACK SENT BLOCKED DONE ADS:** existing ACK/return/advertisement observations while this reply is unpublished. **ACK AGE FIRST GAP LAST GAP:** maximum observed pending-ACK age, queue→first Core entry and last Core observed end→Owner publication.
- Eight **START END CMDKFTXN PARAM** rows show pass entry/end ages, packed choice metadata and full GLINK parameter. `CMDKFTXN=(command.min(255)<<24)|(kind.min(15)<<20)|(flags<<16)|transaction`. Flags: fitting intent1, exact ELF data selected2, callback blocked4, callback uncertain8. Kind is the existing diagnostic kind (registry reply4); transactionFFFF means no typed QMI reply transaction for that choice. Command0/parameterFFFFFFFF means no writer header was observed, such as an idle/no-intent outcome. Command0/parameter0 is an explicit normal follow-up refusal before any callback, not an on-wire header. Such an entry advances pass/timing observations but not the existing callback outcome counters. Successful control callbacks have a real header but no exact-selected flag. Never infer a successful ELF commit from a header alone; the freeze flag and exact publication/completion establish it. Command/kind display saturates at255/15; production GLINK commands are within that range. Structs retain the full values.
- **RECEIPT3 ADMIT RECEIPT4:** bounded same-endpoint receipt journal observations and successful admission; missing journal entries stay unknown. **MCFG PEER STAGE RESULT OP** summarizes the existing postmatching-ELF target, not every earlier MCFG request or its options. IPA/PD/WLAN/WLFW and original final ACK/MCFG counters remain the startup outcome.

The next result can distinguish many costly Core attempts from a long gap before/between attempts, and identify controls/other packets, a missing fitting intent or blocked callback when retained. The journal cannot reconstruct omitted middle choices. No speedup, WLAN request or working WiFi is claimed before boot.
