# Bounded credit then ELF before a fresh grant advertisement

IMG_9808 showed no ready-ELF callback, with12 positive-grant candidate checks excluded by ready credit. The existing converted-credit opportunity is restricted to transaction4. Feature `sunfish-elf-credit-pair-turn` inherits the verified first-live-ELF binding and supplies a two-stage alternative for that exact marked transmit.

## Authority and bounds

The first successful exact domain0 ELF admission additionally marks its actual transmit with a private Boolean. Another private Boolean begins false and records a successful paired credit publication. These reset with the normal transmit constructor; the existing Session once-only binding still prevents a second request from inheriting an opportunity. No capture, timer, diagnostic mask, transaction-number guess or screenshot value supplies authority.

On an **ordinary** call, only the existing ready or converted ELF candidate can supply the pair. It must equal the normal registry candidate, retain its private exact-ELF marker, have no used credit or grant loan, remain ReplyQueued with its own real return complete, and retain normal fitting-intent/flow/queue/route checks. A private conversion token for another opaque handle prevents the pair. The ready/conversion selectors retain their positive-ACK/unadvertised-Advertising backing, cooldown and protected TFTP/WRQ exclusions.

Stage1 uses the **normal first ready QRTR credit** from class1, complete52-byte unstarted RESUME_TX. It may belong to another flow; the code does not assume it is ELF's own credit. The existing per-transmit credit-attempt latch is spent before the checked writer, including WouldBlock or unwind. Only actual writer success on that paired credit sets the new private committed flag. The credit retains its transmit and real GLINK receipt requirement.

Stage2 allows the marked ELF to use its existing per-transmit DATA loan despite the used credit latch **only when that private committed flag is true** and no foreign conversion token intervened. All normal ready-credit priority remains: another ready credit prevents ELF selection. An advertised backing still protects its ACK. The existing grant-attempt latch is spent before ELF's checked callback. A fresh grant cannot reset either stage's used latch. No extra writer loop or Runtime service call is added; ordinary checked invocations perform each stage separately.

A blocked credit cannot enable stage2: normal advertisement/ACK fallback proceeds, followed by ordinary credit/response retry. A blocked ELF attempt similarly falls back to advertisement/ACK and later byte-identical ordinary DATA. Uncertainty or unwind quarantines the Session. Negative ACKs, absent fit/backing, protected TFTP/WRQ work, other registry records and generation/owner checks retain their parent paths. Required advertisement always precedes its ACK, while credit precedes any paired ELF reply.

Conversion diagnostics for the old transaction4 capture are suppressed for a different ELF credit and only closed by a borrowed DATA record matching that capture's actual opaque target. This prevents a newly admitted ELF pair from falsely finishing another request's diagnostic window. It does not authorize I/O. No new optional clock call, hardware read, receive intent, credit grant, queue slot or capability is introduced. Two private Booleans per transmit are the only added authority state.

## Evidence and verification

Actual Core schedules cover clocked/clockless success with own return before/after queue, credit→ELF→advertisement→ACK and both exact GLINK completions, credit-WouldBlock fallback without a DATA loan, ELF-WouldBlock fallback across a second fresh grant with identical retry bytes, and uncertain/unwound writes at either stage with quarantine/reset. Parent cases retain the first-ELF-only binding, other names/offsets/failure exclusion, fit, already-advertised ACK protection and ordinary-versus-bounded-call distinction. Two removal controls independently remove credit eligibility and its successful-commit flag; each makes the real paired-success case fail. Full current and immediate-parent Core suites plus selected Owner/IRQ, physical panel and source-boundary checks are required.

Removing the marked child blocks and Cargo feature recovers the parent production source, with one explicit lexical join in the ready predicate. Selection helpers use only private live state and the normal class1 selector; they cannot read diagnostic windows. Native stack analysis, complete packed boot validation,304 capability mutations and exact pinned-SDK/Normal-NC mapping reproduction bind the image. The SDK is reused, not rebuilt.

In ELF PUB MASK, bit17 (`00020000`) is the borrowed credit attempt, bit18 (`00040000`) its successful publication, bit19 (`00080000`) the ready ELF attempt and bit20 (`00100000`) its successful publication. All four together contribute `001E0000`; other mask bits can also be present. Successful credit publication is distinct from matching GLINK completion. Inspect actual queue→publication time, gates, retained writer records, ELF completion, successful digest errors and independent WLAN/WLFW.
