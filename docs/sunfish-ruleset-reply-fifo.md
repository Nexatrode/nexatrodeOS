## Observation-only increment

Feature `sunfish-ruleset-reply-fifo` inherits the delivered handoff profile without changing its policy. Two bounded watches bind the **second and third distinct accepted ruleset requests**, at the existing immutable startup indices1 and6. These are ordinal requests, not fixed peer-port numbers or assertions of byte-identical retries. Each keeps the original real transport reservation sequence and remote intent, both checked against the authoritative Core lifecycle. Normal startup observation already requires exact reservation/slot/route/length/intent for a done transition.

A watch arms only across normal queue-to-full-publication transition: the original was queued/unpublished before this checked writer pass, and afterward the corresponding original record must show publication of a19-byte ERROR1 under the successful last-fragment DATA's remote intent. An arbitrary later packet with a reused intent cannot arm it. No watch is overwritten. The getter returns the bounded cached binding; rendering requires that binding to match the original sequence and suppresses a mismatched display join.

The watch initializes from the checked writer's already validated TX/RX cursor pair. Each successful normal Ring sample reuses its existing TX-tail consumption delta, RX-head advance and unread count. The two watches share a new optional start/end CPU clock pair for that validation sample; there is no new FIFO/status read or validation operation. Each keeps its own remaining TX boundary and bounded RX history. Invalid samples cannot advance the watches. Optional clocks are also sampled at arm. Additional clock calls, metadata copying, larger retained state and rendering may perturb timing, even though the complete Fake I/O and committed wire remain equal in the paired replay.

Completion requires the original authoritative record's done bit to rise during this normal ingest, the same original sequence, matching remote intent, and the actual8-byte RX_DONE/RX_DONE_REUSE header and ID. A bare remote-intent number is insufficient. The existing window maps the matched record's end into recorded head-advance spans to recover last-absent/first-visible bounds and bytes ahead. Missing or evicted spans stay unavailable. A validated exact peer-close transition records the RX head/unread count when **the host processes that close**, allowing a later matched completion to report whether it was already visible then. This is not the close's first FIFO-appearance time. Close after watch completion is not retroactively sampled, and close before watch arm has no reconstructed sample.

Both watches clear on actual transport reset only after the existing fresh-generation/identity/empty-ring validation succeeds. No queue admission, request selection, service/writer turn, grant ordering, QRTR accounting, close cleanup, buffer retirement, file content, firmware provider, capability or memory mapping changes. Both Adapter/Ring construction paths initialize the new observation fields. The compile-time bound is4096bytes per private watch; fresh native stack validation gates delivery. This does not authorize new packet or device operations.

## RULESET REPLY FIFO

All timestamps are hexadecimal microseconds on this runtime clock; all ones means unavailable. Ordinary phase flags and known numeric zero remain distinct from missing clocks. A missing watch does not mean no request was received: its original row can show queued but not yet successfully published.

Rows2–4 show runtime/close state and ruleset total/omitted count; ELF receive/queue/publication/Owner completion/body match/credit mask; the inherited handoff service count/result/flags, writer-group count and TX3 calls/mask. No new handoff is enabled by this observer beyond the inherited runtime profile.

Rows5–10 are RULE2; rows11–16 are RULE3. Each six-row block shows:

1. Original peer, phase flags, reservation sequence low/high and watched remote intent.
2. Accepted request, dispatch, queued, publication, exact Core completion and processed close clocks.
3. Watch arm, observed modem TX-tail crossing, TX bytes still ahead of the watched boundary, RX unread at arm and RX unread when its exact close was processed. `TX LEFT=0` is a clock-independent consumption latch, even if the tail clock is unavailable.
4. Matching receipt's last-absent/first-visible bounds, bytes ahead at first visibility, whether visible at processed close (0/1/unavailable), watch finished and RX-history eviction count. An unavailable last-absent bound may mean the receipt was already visible at arm; it is not evidence of delay. Evicted history cannot supply a new precise bound.
5. Reply opcode high16/code low16, host transfer port, reply body length, admission attempts, FlowBusy and NoCapacity counts.
6. Request body length, numeric option-presence mask, parse flags, rsize, timeoutms and last client ACK/ERROR projection. The same-peer request's options do not identify another reservation. Phase flags1/2/4/8/16/32/64/128 mean accepted/dispatched/reply formed/queued/published/matching completion/client ending/close;512 denotes missing transport reservation.

Rows17–24 retain the original RULE1, RULE4, EFS1 and EFS2 identities and receive/queue/publication/completion/close clocks. These are the retained entries; EFS total/omitted counts are not printed on this child page, so do not assert they cover every possible EFS request. Ruleset total/omitted count remains explicit above. Rows25–28 show live IPA counters/pending ID, the separately bound ELF FIFO/receipt bounds, original DATA/final-ACK/close, historical IPA/PD/WLAN/WLFW and RAM MCFG writes/file length. ELF tail/visibility belongs to ELF, not to either watched ruleset.

Subtract original publication from observed tail to bound transport consumption; tail to first-visible estimates the pre-RX gap; first-visible to original done identifies remaining host processing time. The absent/visible sampling bracket and any missing clocks bound precision. These are ordered observations, not exclusive CPU accounting or a causality proof. A new boot can follow a different request pattern and need not reproduce the prior gaps.
