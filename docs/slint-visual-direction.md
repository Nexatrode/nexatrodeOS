# Slint visual direction

Use the clean Personal OS mockup as the usability baseline and Aurora as the
source of visual character. The result should feel like one phone interface,
not a terminal skin.

- Keep the clean mockup's spacing, hierarchy, and readable type as the default.
- Use “Personal OS” as the everyday interface name. Reserve “NexatrodeOS” for
  the About/version identity and internal project metadata.
- Use Aurora's cyan, violet, and amber accents for focus, selection, and
  workspace identity.
- Keep glitch effects optional and sparse: wallpaper, transitions, or a theme
  preview. Do not put scan lines or distortion behind small text or controls.
- Use the shield for Lockdown and other protection states; keep security
  language calm and clear.
- Use phone-native labels and navigation. Avoid desktop-terminal details such
  as `calc.exe` or `> ls` in normal app screens.
- Keep status text, touch targets, and contrast readable at the tested UTM and
  phone resolutions. Decorative effects must not obscure state or input.

This direction combines the two supplied Personal OS screen sheets: the clean
sheet provides the layout and legibility baseline, and the Aurora sheet provides
the restrained accent palette and optional atmosphere. Apply it to Slint screen
work without implying that demo data, network services, or security controls are
already functional.
