# Exact ELF transmit-pool ownership

[IMG_9724](sunfish-elf-third-phases-IMG_9724.md) identifies reason2 at the first/latest failed ELF admissions: all eight ordinary transmit slots are occupied. Both same-peer registry owners are already eligible for third admission. This does not identify the other six packets or which real release makes room. Older port0x49 pool captures are a different boot/request and cannot substitute for this snapshot.

Feature `sunfish-elf-tx-slots` adds a bounded header-only observer for the exact first accepted ELF handle. On reason2 it retains opening and latest eight-slot snapshots. On the **first subsequent actual ordinary-slot clear**, it records index, time, release-path code, current empty-slot mask, and that slot's original opening-snapshot identity. The initial full pool guarantees the first released index still belonged to that original packet. The trace freezes on exact ELF queue success, recording its assigned index and remaining empty mask. Reset discards the trace; reserved OACK-slot releases cannot masquerade as normal capacity. No payload bytes are copied.

Every normal clearing site is covered after the actual assignment, including protocol retirement and validated unpublished cancellations. Normal retirement remains behind its existing GLINK/QRTR conditions, exact completion validation, flow accounting and router-ticket completion. Observation has no effect on those conditions. Source comparison removes only gated metadata hooks, types and the diagnostic retirement argument to reproduce the prior logic. Owner work, Runtime service loops, FIFO checks, grant advertisement/ACK order, queue limits and all credits remain unchanged. No early retirement or larger pool is introduced.

## Panel decoding

Title **ELF TX SLOT OWNERS**. The opening/latest blocked times and failure count are followed by the first actual free index/cause/mask, then that original packet's identity. Eight pairs of rows display the **latest blocked snapshot**, slots0 through7 in order. A changed mask compares the complete opening/latest records. It is possible for the first free to precede the latest full snapshot if another packet occupies the released slot before ELF retries; compare times, masks and identities rather than assuming the opening and latest owners match.

Each metadata word is `kind << 24 | flags << 16 | op`. Kinds:1 RESUME,2 QRTR control,3 RMTFS reply,4 registry reply,5 other QMI reply,6 TFTP,7 IPA,8 other native client. Flag bits:01 occupied,02 started,04 fully published,08 GLINK done,10 local QRTR retirement condition satisfied,20 remote slot owned,40 reference-flow reservation retained. These flag meanings differ from the older two-owner window's packed flags. QRTR credit state is not equivalent to per-packet application acceptance.

For TFTP `op` is its big-endian opcode. For typed QMI packets it is QMI kind; message/transaction are in the following row. For other/control packets it is the QRTR header type. The next three words are source port, destination port and remote intent ID. The second row is `length << 16 | bytes_sent`, `transaction << 16 | message_id`, full source node and destination node. Non-QMI transaction/message remain FFFF. Length bounds are checked at compile time. FFFFFFFF means unavailable; a first-free original intent can be unavailable if that packet had not published at the opening snapshot. This is not a claim that its later completion lacked an intent.

Release causes:1 exact GLINK RX_DONE retirement,2 matching QRTR RESUME retirement,3 validated unpublished firmware-close cancellation,4 completed RMTFS client-close cleanup,5 queued TFTP retry cancellation,6 unpublished original OACK cancellation. These are trace labels on existing release paths, not new permissions to release. No record is generated by invalid completion, blocked/uncertain write, failed precondition or a QRTR/GLINK condition that leaves ownership outstanding.

Existing receive/registry phase timings and IPA/PD/WLAN/WLFW outcomes remain displayed. The misleading zero publication-I/O row is removed: the old I/O observer only measures enabled `service_owner` dispatch and excludes the queued ELF turn. Its retained counters remain useful within that scope, not as complete elapsed-operation coverage.

## Verification and limits

New Core schedules exercise mixed full-pool identities, opening/latest distinction, first RX_DONE retirement and exact index reuse, GLINK-before-QRTR retention and later exact RESUME release, invalid/blocked/uncertain events, clockless operation, reset and frozen snapshots. Renderer testing uses the actual dual framebuffer with all eight records, packed identifiers/lengths, a changed slot, missing/clockless captures and row bounds. Existing third-admission, fault, grant, backpressure, transfer and actual Owner/IRQ suites remain required. Paired ordinary protocol fixtures test behavior parity; they do not establish handset deadlines.

Native verification includes the rebuilt AArch64 payload, selected stack headroom, actual capability mutations, boot layout and packed initializer mappings. The pinned previously rebuilt Normal-NC SDK is reused and reproduced. The observer adds bounded CPU copies and optional clocks, so it can perturb timing. Opening/latest metadata omit intermediate states. Selected stack analysis excludes TLS, indirect calls and other descendants; it is not whole-program worst-case proof. No working-WLAN outcome is claimed before physical testing.

## Cold temporary boot

Fully power off, enter fastboot with Volume Down + Power, then:

```sh
cd /Volumes/untitled/sel4-personal-os &&
"$HOME/Library/Android/sdk/platform-tools/fastboot" -s 02281FQC200058 boot \
  .cache/sunfish-native-wifi/private/native-elf-tx-slots-v1/fastboot.img
```

Wait at least one minute, then send the full settled panel. No partition flash or automatic device action is performed.
