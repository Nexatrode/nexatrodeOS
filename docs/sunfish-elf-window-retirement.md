# Exact ELF admission occupants and matching receipts

Follow-up to [IMG_9713](sunfish-elf-queued-handoff-IMG_9713.md). This image retains the successful bounded ELF queued handoff and adds **observation only** at existing admission/receipt boundaries. It does not enlarge the two-reply window, release a buffer early, change FIFO validation, grant ordering, QRTR credit, close handling, IRQ ownership or firmware policy.

## Offline findings and the missing current-boot evidence

The existing notes already resolve the general ordering question. [IMG_9707](sunfish-registry-elf-IMG_9707.md) showed transaction 3 completing 203.120 ms before ELF queued, while transaction 4 completed 74.592 ms after queueing. [IMG_9708](sunfish-registry-tx3-IMG_9708.md) showed transaction 3's reply consumed promptly, but a much later matching receipt. Those are earlier boots. They do not provide transaction 3's missing completion or both live occupants for IMG_9713.

In IMG_9713 the new queue handoff worked: ELF published inside the extra turn, 93.099 ms after queueing. Its larger 2,700.034 ms selection-to-admission interval contained eight same-peer rejections. Transaction 4 published 2,013.141 ms before ELF queued and completed after ELF publication. The historical peer field is not a unique blocker: `record_registry_pressure` overwrites its peer fields while walking all active transmits. It cannot distinguish two fully published owners from a remaining unpublished owner using a single displayed entry.

Normal admission permits one older, fully published registry reply with its own remote intent and reference-flow reservation. Two earlier same-peer packets block another reply. A validated receipt for **either** of the earlier replies can free a slot; the other still owns its original bytes/intent. If the survivor is unpublished, receipt alone is insufficient: it must publish before normal admission allows another reply. A real reference-credit rejection can occur with zero older packets. These are distinct conditions, not reasons to skip checks or retire at publication.

Fresh actual-Core replays cover both receipt orders with and without a clock, an unrelated peer completion, an unpublished survivor needing publication after a receipt, invalid receipt and reset, frozen exact ELF completion, history across request/intent reuse, and actual reference-credit pressure. The actual Owner startup-chain fixture also asserts the two occupants and the matching receipt before admission in both orders, retaining the other packet's identity/bytes. A paired on/off run compares committed writes across the modeled 3/4/ELF exchange. These are finite ordering proofs, not reconstruction of IMG_9713 or measurements of modem deadlines.

The next boot will identify the missing **current** boundary: both occupants at the first/last failed ELF admission, the matched receipts and remaining count, then the occupants at actual successful admission. It also reuses the exact transaction-3 FIFO peer-tail/receipt visibility and transaction-4 clocks. It is not another isolated queue-publication timing probe.

## Capture identity and limits

`sunfish-elf-window-trace` starts at the first validated `kernel/elf_loader` request. Its private opaque owner/generation/request identity and exact local/peer address pair bind all records. No transaction number alone selects the target. Failed admission records are taken from the existing normal rejection path; a successful record is taken only after normal staging succeeds. The successful snapshot excludes the newly queued ELF reply so its count concerns earlier owners.

The first and latest failed snapshots each retain the count of **all active same-destination transmits** and the first two entries with QMI transaction, kind, state and remote intent. Entry A/B are storage iteration order, not oldest/newest order. Counts can expose omitted entries if an unexpected state has more than two; the observer does not repair it. Private request handles distinguish a later reuse of an intent or transmit slot.

A receipt is recorded only after the normal decoder validates the exact fully published intent, finishes normal reference-flow processing and attempts normal retirement. The saved typed route and opaque request identify it after the transmit slot can be erased. Remaining count is the actual post-retirement state, not a command to release anything. Only matching registry endpoint pairs are retained. The exact ELF receipt freezes the capture; trusted generation reset clears it. Invalid or unrelated receipts cannot advance it.

Receipt history retains opening two/latest two, with total and omitted counts. A monotonic observation sequence orders failed/successful snapshots and receipts independently of an installed clock. `LAST RX` is merely the last matching receipt before admission. It is **not by itself proof that the receipt was the last cleared condition**: the unpublished-survivor replay deliberately has a last receipt of transaction 3 but needs transaction 4 publication afterward.

There are no new device-read sites, packet payload copies or allocation. Small private snapshots and optional clock calls add overhead. Existing normal runtime service/dispatch/paint methods, Core writer/receive policies and FIFO I/O methods remain unchanged; stripping the feature-gated observation statements exactly reproduces the prior changed Core methods. Existing service-registry outcome changes trigger display updates under the retained repaint gate. This is self-review, not independent review or a proof of every hardware interleaving.

## ELF WINDOW RETIREMENT panel

All values are hexadecimal. Times are microseconds from runtime start. `FFFFFFFF` means missing/unknown where applicable, not elapsed time. Presence and stage bits distinguish absent observations from real numeric zero. Independent integer time conversion can differ by one microsecond from subtraction of displayed ages.

- **ELF RX QUEUE PUB DONE:** existing exact request, queue, full publication and matching completion. **TURN ARM ENTER END FLAGS** retains the queued handoff; its flags are armed=1, consumed=2, entered=4, returned normally=8, exact ELF published/completed by end=16, dispatch failed=32.
- **ADMISSION TRIES RECEIPTS END:** number of recorded normal ELF admission outcomes, matching-pair receipts, omitted receipt history and clock-independent frozen flag. The observer records normal reasons 1..5 plus success; invalid-handle/reply errors before those boundaries are not relabeled as admission outcomes.
- **TX3 QUEUE PUB TAIL DONE:** existing predecessor queue, full publication, sampled peer consumption and exact completion. **TX3 ABS VIS AHEAD END LOST:** receipt absence/visibility bounds, preceding byte count, and `matched<<16 | saturated_history_evictions`. These legacy rows refer to the original transaction-3/peer-0:9 capture, as in the prior boots; they are not inferred from an arbitrary entry labeled 3. The new snapshots themselves bind the exact ELF endpoint pair.
- **TX4 RX QUEUE PUB DONE:** existing transaction-4 clocks. **RX END REG ENTER SELECT / PHASE US RX REG SELECT Q:** existing four prequeue phases; they do not assign all elapsed time to a remote wait.
- **FIRST FAIL US RS N GATES / LAST FAIL US RS N GATES:** first/latest rejected admission clock, packed reason/sequence, prior same-peer count and observed gate bits. `RS=(sequence<<8)|reason`, with the displayed sequence saturating at 24 bits. Reasons: 1 same-peer conditions, 2 TX slots, 3 legacy-flow capacity, 4 reference credit, 5 reference-flow capacity.
- **OWNER A/B TXN FLAGS ID KIND:** each matching prior packet's transaction (FFFF for a non-QMI-reply kind), state flags, owned remote intent or missing marker, and existing diagnostic kind (4 is a registry reply). Flags: bytes sent=1, fully published=2, GLINK done=4, local QRTR retirement condition=8, remote slot owned=16, reference token present=32. Bit 8 is not a received RESUME or proof of remaining destination credit.
- **GATES**, observation only: multiple earlier owners=1, non-registry reply=2, different local endpoint=4, not fully published=8, no owned remote slot=16, already GLINK-done but still retained=32, local QRTR retirement condition unsatisfied=64, no reference token=128. Bits are ORed across earlier entries and do not establish one unique cause. The **actual reason** remains authoritative: reason 4 with count/gates zero is possible and tested. This is not the normal policy reading a diagnostic mask.
- **ADMIT US N GATES LAST RX:** successful normal admission clock, earlier-owner count and conditions, and last same-pair receipt's transaction before admission. Compare the failed/admitted entries and the receipt state; do not conclude causation from `LAST RX` alone.
- Four **RETIRE US TXN ID STATE** rows: exact validated GLINK receipt clock, QMI transaction, remote intent, packed state after normal retirement. `STATE=(sequence<<16)|(target_ELF<<9)|(member_of_last_failure<<8)|remaining_count`, with displayed sequence saturating at 16 bits. A row does not itself release an intent or prove application acceptance. The member bit uses the opaque request identity from the latest failed snapshot at that event, not the intent ID alone. Remaining count excludes the target ELF, as admission snapshots do.
- **RECEIPTS OMIT ADMIT SEQ FLAGS:** receipt totals/omissions, successful admission's observation sequence and flags: started=1, saw failed admission=2, admitted=4, a member of a then-last failure completed=8, exact ELF completed=16. Flags can advance without a clock; bit 8 is not a claim about the last cause of admission.
- **MCFG PEER STAGE RESULT MASK / MCFG BLK TIME WIN TSIZE / MCFG RSIZE SEEK UNLINK FLAGS / MCFG FILE OP ERR LEN:** reuse the full existing MCFG capture omitted by the previous summary. They show the actual native server result, offered numeric options and presence/parse flags, committed file state before dispatch, prepared response opcode/error/body length. Native result zero means successful server processing, not successful file lookup. Request option mask: block=1, timeout=2, window=4, tsize=8, rsize=16, seek=32, unlink=64. Parser flags are malformed=1, invalid number=2, duplicate=4, unknown=8, overflow=16, oversized=32, mode=64. Stage bits remain received=1, dispatched=2, nonempty reply=4, queued=8, published=16, completed=32, client ACK/ERROR=64, close=128. An unprepared reply's fields are unavailable; ERROR is populated only for an actual opcode-5 response. No option or firmware policy was changed.
- **IPA PD STATE WLAN WLFW / ORIG ACK MCFG W FILE READ:** startup outcomes and original final-ACK completion, with MCFG counters. A valid one-byte file and completed ELF exchange are not WLAN firmware loading.

For the next result, identify the last failed window (two owners versus an unpublished survivor), which exact receipt reduced it, and the admitted state. Then check whether ELF completion is followed by WLAN RRQ/WLFW. The image does not predict those outcomes.
