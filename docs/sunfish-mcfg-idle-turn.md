# One retained-MCFG opportunity at normal receive idle

IMG_9768 showed that the queue-success-only eager turn was too late: pending RX led directly to the watched client's close. An earlier validated normal idle sample preceded predecessor publication by 97.618 ms, its matching completion by another 25.718 ms, and target admission by another 73.227 ms. The target could not bypass the still-live same-peer predecessor at that sample.

`sunfish-mcfg-idle-turn` gives the normal checked writer a bounded opportunity in that earlier window. It applies only when the existing Owner option is enabled, normal `poll_receive` returns validated `Receive::Idle`, and the Owner holds an unspent, immutable missing-MCFG ERROR response on a known MCFG peer/transfer route. Each retained reply owns a private one-use latch, consumed before fallible I/O and removed with that reply on admission or close. At most one such opportunity is allowed per bounded Owner work call. No observer flag, clock, packet counter or diagnostic reservation selects this work.

The opportunity lends at most four ordinary writer calls, using the same checked loop as the existing queue-success burst. It can return a GLINK receive buffer, publish the backing advertisement, commit its ACK, and send whichever DATA the normal arbiter selects. Any DATA ends the burst, including QRTR credit or unrelated DATA; no particular packet is forced. Fresh sampled RX/early state is checked before selection and the existing pre-write/pre-head checks stay enforced. Backpressure and new RX stop the loan; normal retries remain. Faults remain terminal, including partial commit failures. Actual committed-operation outcomes, not diagnostic counters, are returned to normal Owner progress accounting. A read notification sent while blocked counts as activity just as in the ordinary writer; the idle-write diagnostic counts Session operations separately.

The original retained reply is **not admitted by this hook**. Its predecessor keeps the original GLINK/flow state and must receive its genuine matching completion. The existing dispatcher then retries the normal queue checks. The feature does not retire a published slot, bypass a same-peer flow or QRTR credit, synthesize a completion, alter MCFG file policy, relax grant ordering, or change close cleanup. Ordinary writer work still runs under its existing policy after the bounded opportunity.

An actual Owner/Adapter synthetic full-pool replay produces RX_DONE → advertisement → positive ACK → the predecessor ERROR. The target remains retained until the real predecessor receipt, then completes against its own later receipt. Both paths produce the same initial 104 wire bytes and four head stores/readbacks. With the new idle opportunity disabled in the comparison arm, the ordinary baseline uses 68 Fake status observations and 28 cursor snapshots; the bounded path uses 58 and 23. No RX packet read is skipped in that empty-input fixture. These counts demonstrate fewer intervening empty polls/Owner refreshes, not measured handset time or proof of meeting the client's deadline. Every individual write retains its validation boundaries.

Tests also cover one opportunity per logical reply and per work call, default-off and foreign-scope behavior, pending close, invalid lifecycle, pending/racing RX, backpressure, uncertain writes, and real receipt identity. The earlier queued-turn, receive-veto, IRQ, fault-injection and firmware/close suites are retained. Negative controls disable the new opportunity or its fresh RX guard and must fail the selected test. Disabled-feature source normalization compares exact marked additions against `8dfeedce`; Core arbitration, QRTR flow policy, native IRQ/runtime authorization, file provider and close cleanup remain unchanged.

The panel is **MCFG IDLE RETAINED TURN**. It retains the RX veto records and target/predecessor/ELF/IPA outcomes. Row 14 reports total RX events, omitted events, **idle-turn calls**, committed idle-turn writes, idle-turn RX vetoes and backpressure stops. RX event call IDs still use the shared bounded-writer call counter (both queue-success and idle opportunities); do not equate them with the idle-only call count. Existing framing/header observation limits remain, including disarming at normal idle, unknown timestamps, initial-DATA-only QRTR decoding and actual DEL_CLIENT node/port. Rows 27–28 retain close and MCFG/WLAN outcomes. Every row stays within the physical 57-character budget.

The private ready profile is `.cache/sunfish-native-wifi/private/native-mcfg-idle-turn-v1`. Its final manifest pins the exact committed revision, source/ELF/image hashes, selected-stack limit, authority audit and actual packed initializer archive. Prior delivered artifacts are immutable. The pinned SDK is reused; the native program is rebuilt and packed loader/report/CapDL/archive are independently reproduced. The cold boot remains manual.

The next handset result should show whether the idle opportunity actually ran, which normal operations committed, and whether predecessor and target publication/completion beat the close. WLAN RRQ/WLFW must be read independently. Saved Linux reaches WLAN before its later MCFG/digest exchange, so this experiment alone does not establish a WLAN prerequisite or predict working Wi-Fi.
