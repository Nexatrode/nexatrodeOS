# Pixel 4a grant eligibility replay

Run `python3 experiments/sunfish-grant-replay/replay.py` from a checkout with Rust 2024, Git, Python 3.11 or later, and the existing Linux RMTFS reference fixtures. The host transport harness reads the two C reference outputs at compile time. The defaults are `.cache/sunfish-native-wifi/private/linux-rmtfs/linux-scm.txt` and `.cache/sunfish-native-wifi/private/linux-rmtfs-server/wire.txt`. To use fixtures from another checkout, set `SUNFISH_LINUX_RMTFS_C` and `SUNFISH_RMTFS_WIRE_C` to their paths. The existing Sunfish reference runners are `platforms/sunfish/test-native-linux-rmtfs.py` and `platforms/sunfish/test-native-linux-rmtfs-server.py`.

The replay builds the real Rust owner and FIFO in temporary host directories and exercises 46 close schedules per policy. It checks the original transfer port, committed TX heads, grant ordering, and the four schedules matching the IMG_9638 panel. Snapshot counts measure ordering in the simulated FIFO. The two alternative policies exist only in the replay patches. The INIT CLOSE VISIBILITY phone image used the baseline writer.

The three historical policies use the sources from Wi-Fi checkpoint `e7d8b0d1`. Run `python3 experiments/sunfish-grant-replay/test_paired.py` to test the checkout’s current driver with the paired OACK and INIT feature. The fixture injects the exact port 0x1f close and checks actual FIFO head advances. Linux GLINK memory and transport reference fixtures are read from the same private cache (or the directories named by `SUNFISH_GLK_MEMORY_C` and `SUNFISH_GLK_TRANSPORT_C`).

On the paired policy, the OACK precedes the close for each of the four placements matching the Pixel trace. INIT also precedes the close at offsets 24 and 25. The replay does not inject TFTP DATA. On hardware, the PAIRED OACK AND INIT panel reports FIRST DATA US for the original client.
